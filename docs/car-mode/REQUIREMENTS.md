# 车载模式需求基线

## 功能需求

- `CAR-F-001`：原型菜单提供车载模式入口和明确退出方式。
- `CAR-F-002`：车载模式使用独立状态机，不复用会联动底座动作的通用情绪接口。
- `CAR-F-003`：至少支持巡航、等待、加速、减速、急刹、颠簸和传感器异常。
- `CAR-F-004`：左右转和倒车仅在输入来源可信时启用。
- `CAR-F-005`：高优先级事件可打断普通状态，结束后根据当前条件恢复。
- `CAR-F-006`：支持表情资源包切换或构建期选择。

## 非功能需求

- `CAR-N-001`：目标硬件为 CyberVoc Board V2.0，屏幕资源基准为 360×360 EAF。
- `CAR-N-002`：资源总量不得超过目标 assets 分区，并保留升级余量。
- `CAR-N-003`：不得用高频闪烁表达驾驶事件；夜间亮度独立于事件状态。
- `CAR-N-004`：传感器异常或数据过期时进入安全降级状态。
- `CAR-N-005`：不降低原固件语音、网络、OTA、菜单和基础显示功能的可用性。
- `CAR-N-006`：每个完成项必须具有编译结果；硬件相关项还必须具有实机证据。

## 待确认需求

- 左右转信号来源：IMU 推断、蓝牙、串口/CAN 网关或人工触发。
- 倒车信号来源及电气接口。
- 首发表情包及是否允许用户运行时切换。
- 车载模式启动方式：菜单手动进入、开机记忆或外部信号进入。

需求发生变化时保留原编号，在下方记录变更原因和日期，不静默改写验收口径。
