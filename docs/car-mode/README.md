# 赛博喵伴 2.0 车载模式开发

本目录是车载模式的持续开发入口。每次迭代必须同时维护需求、实现、验证和提交记录，避免功能代码与设计依据脱节。

## 文档索引

- `ROADMAP.md`：总体路线、阶段目标和完成标准。
- `REQUIREMENTS.md`：稳定需求、约束和验收口径。
- `ITERATION_LOG.md`：每次迭代的状态、范围、测试和提交记录。
- `UPSTREAM_SYNC.md`：个人仓库与官方上游的同步流程。
- `iterations/`：每个迭代的详细计划与结果。

## 每轮开发流程

1. 新建或更新 `iterations/CAR-xxx.md`，写明目标、范围、非目标、验收标准和风险。
2. 在独立分支实现，保持一次提交只解决一个清晰问题。
3. 至少完成编译检查；涉及硬件时记录实机型号、固件版本、测试步骤和结果。
4. 更新迭代文档与 `ITERATION_LOG.md`，记录遗留问题。
5. 提交并推送到个人仓库；合入 `main` 前保持上游同步且解决冲突。

未经实机验证的项目标记为“待实机验证”，不记为完成。
