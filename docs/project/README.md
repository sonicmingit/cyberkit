# 喵伴 2.0 项目开发记录

本目录维护整个喵伴 2.0 固件的需求、迭代和开发日志；`docs/car-mode/` 继续保存车载模式专项设计与验证记录。

## 文件结构

- `REQUIREMENTS.md`：项目级需求基线、优先级、状态和验收标准。
- `DEVELOPMENT_LOG.md`：按日期记录实际修改、验证、提交和遗留问题。
- `iterations/`：每轮迭代的范围、计划、测试和完成结果。

## 持续更新规则

1. 开始开发前先更新需求状态，并建立对应迭代记录。
2. 需求变更保留编号和历史，不静默覆盖原有验收口径。
3. 每次实现后记录修改文件、测试方法、结果和 Git 提交。
4. 未编译的功能不能标为“已完成”；依赖硬件的功能还需标注实机验证状态。
5. 官方上游合并、冲突处理和回归结果也写入开发日志。

## 状态定义

- `待细化`：目标已提出，交互或技术口径仍需确认。
- `已计划`：范围和验收标准已确定，尚未实现。
- `开发中`：正在实现。
- `待验证`：实现完成，等待编译或实机验证。
- `已完成`：实现和规定验证均通过。
- `已阻塞`：存在明确且尚未解除的外部阻塞。
