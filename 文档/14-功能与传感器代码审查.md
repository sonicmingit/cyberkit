## 一、应优先修复的问题

### R01 / P1：构造期重新获取主板单例，阻断启动

位置：`main/boards/CyberVoc-Board-V2_0/customer_ui/feature_ui.cc:451`、`:144`。

调用链：`Board::GetInstance()` → `create_board()` → `EspS3Cat` 构造函数 → `Initializest77916Display()` → `start_lvgl()` → `ui_bridge_init()` → `feature_ui_create()` → 同步 `UiRefreshCallback(nullptr)` → `UpdateSettingsLabel()` → 再次 `Board::GetInstance()`。

`Board::GetInstance()` 使用函数局部静态指针，第一次初始化尚未返回。ESP-IDF 5.5.2 的 `components/cxx/cxx_guards.cpp` 在调度器已运行、guard pending 时等待初始化完成；同一构造链无法完成这个等待。关闭静态初始化保护也不能修复递归构造。结果可能表现为启动停住，而触摸初始化位于显示初始化之后，尚未执行。

建议：初始化 UI 时注入构造中的板级引用/状态提供者，或将依赖 Board 的初始刷新与定时器启动延迟到构造完成之后；仅删同步刷新还需避免定时器在构造结束前触发。验证冷启动日志确实经过 `Feature UI initialized`、屏幕触摸、GPIO8 和 QMI 初始化。

### R02 / P1：点击车载开关从 PSRAM 栈任务直接写 Flash

位置：`feature_ui.cc:238`、`:536`；板级 `CyberVoc.cc:260`。

`MenuEvent()` → `HandleMenuItem()` → `feature_car_set_enabled()` 同步创建可写 Settings、写入 NVS 并在析构时 commit。LVGL adapter 明确配置 `stack_in_psram=true`，当前 sdkconfig 未启用 PSRAM XIP。ESP-IDF `spi_flash/cache_utils.c` 的缓存关闭入口检查当前栈是否在可用内部内存，写 Flash 的任务栈位于 PSRAM 时存在断言/缓存访问异常。

建议：菜单只投递命令，由应用或内部 RAM 栈任务完成业务状态与 NVS 更新；UI 显示服务结果。不建议用改全局内存配置绕过这一调用边界。开关快速连点、存储失败和重启持久化均需验证。

### R03 / P1：滑动没有消费后续菜单点击

位置：`feature_ui.cc:253`；`ui_bridge.cc:473`；依赖 `managed_components/lvgl__lvgl/src/indev/lv_indev.c:1449`。

菜单是一个不可滚动的可点击父容器，命中项目取释放位置。全局手势在 RELEASED 时设置忽略点击标志，但 `MenuEvent()` 不读取该标志，也不检查按下位置、移动距离或手势是否已经消费。当前 LVGL 在 RELEASED 后、未形成滚动对象时继续派发 CLICKED。

主机抽取原函数复现：在菜单 `(180,340)` 按下，滑到 `(180,70)` 再发 CLICKED，执行了一次菜单操作；这是上滑收起时可能同时切换 CAR 的路径。被判为非导航拖动的动作也没有取消点击资格。

建议：统一维护一次触摸序列的所有权；超过拖动阈值即取消点击/长按资格，导航后消费后续事件。单击应要求按下和释放属于同一有效项目。长按结束不能再执行短按，PRESS_LOST 应按取消处理。不要只调整触摸灵敏度掩盖事件冲突。

### R04 / P1：QMI 字节序配置与解析不一致，需先于阈值调参验证

位置：板级 `CyberVoc.cc:733`、`:752`。

代码写 `CTRL1=0x60`，随后用 `le16` 拼接六轴值。QST QMI8658A Rev A 手册第 30 页定义 bit5=BE，置 1 为大端、清零为小端；0x60 同时置位自动地址递增和 BE。因此按所声明的 QMI8658A 规格，该配置和解析方式不匹配。[QST 原厂数据手册（Waveshare 镜像）](https://files.waveshare.com/upload/5/5f/QMI8658A_Datasheet_Rev_A.pdf)

例如 ±8g 量程下 +1g 的数值为 4096（0x1000）；若按大端返回 `10 00`，现解析为 16，即约 0.0039g，无法通过静止标定。这是字节交换示例，不是设备采集结果。

建议：先记录芯片版本和 CTRL1/2/3/7 回读值，静态六面放置同时输出原始字节与换算值；确认实际硅片行为后将 BE 配置和解析统一。可以选择显式小端配置配合现有解析，但本轮不在没有实机证据时直接改寄存器。现有 4096 LSB/g、64 LSB/dps 与配置的 ±8g/±512dps 量程本身相符。

### R05 / P1：重力方向固定，坡道/安装角变化被当成持续加速

位置：`car_mode/car_motion.h:68`、`:148`。

标定后 `gravity_`、`up_`、`forward_` 不再更新，运行时始终减去初始重力。主机用 50 Hz 输入从水平缓慢转到 10° 的纯重力向量及对应缓慢俯仰角速度，随后保持无旋转、无平移；等待两秒后仍输出 `accelerate`。初始前向投影中约 0.174g 的重力分量超过 0.10g 门限。

建议：引入带加速度可信度判断的陀螺姿态传播/互补重力估计，避免把持续车辆加速全部吸收到重力估计中；或者对姿态变动明确降级并要求重校准。补充上下坡、手持倾斜、松动和长时间零偏回放，再讨论实车阈值。

### R06 / P2：启动缺失的 IMU 后续不会恢复，也可能只显示“校准中”

位置：板级 `CyberVoc.cc:868`；`feature_ui.cc:527`、`:585`、`:149`。

QMI 未探测到或初始化失败时不创建采样任务，只调用一次 `feature_car_mark_sensor_lost()`；而默认车载关闭时该调用立即返回。之后用户开启车载，只重置状态并等待样本，没有新的探测或超时检查来源，可能一直处于 Cruise/未校准。设置页又把所有未校准状态统一显示为 CALIBRATING，不能直接显示已丢失的传感器。

建议：将设备在线/读数新鲜度与车载 enabled 分开维护，使用独立心跳或监督任务检查超时，探测失败低频重试；初始化失败释放设备句柄，检查采样任务创建返回值。状态页区分关闭、未探测到、校准中、轴向无效、已就绪和数据失联。

### R07 / P2：取消计时器不能使已排队的提醒失效

位置：`feature_ui.cc:162`、`:170`、`:504`。

`CountdownFinished()` 将状态置为完成后无条件排队提示和声音；取消只改 timer_state，不使已排队 lambda 失效。抽取原函数复现“到期回调 → 取消 → 应用队列执行”后，声音仍播放一次。重新启动计时也可能收到上一次提醒。

建议：计时任务加入 generation/token；开始、取消和重设时更新，执行提醒前再次验证 token 和状态。进一步覆盖 ESP timer 回调已出队但尚未获得 timer_mutex 时的并发重启，防止旧回调将新计时置为完成。`resume` 失败也应回滚 RUNNING 状态。

## 二、触摸传感器专项结论

### 屏幕触摸 CST816S

- 板级驱动使用共享 I2C、400 kHz、GPIO11 下降沿中断，360×360，坐标镜像/交换与显示一致。没有从这些配置直接证明接线错误。
- 当前关闭芯片 ID 读取，且触摸 RESET 为 NC；构造成功日志仅证明驱动对象建立，不足以证明真实设备可读。必须检查实际中断、坐标及按下/释放数据。
- LVGL adapter 的 IRQ 读取路径在没有新中断时返回上一触摸状态。丢失释放中断/控制器异常时存在保留按下状态的风险；需在板级适配中评估按下期间的轮询兜底或超时取消，不能未经验证修改所有板型的第三方驱动。
- 旧导航只接受顶部/底部 30px、横向中心 ±50px 起点，位移需至少 80px；两轴都超过 80px 会当成拖动。用户从圆屏中央下滑或斜滑无反应可能是手势规则，而非传感器坏了。
- 确定的输入冲突见 R03；优先统一手势取消机制，再调整边缘区域、主方向比值及日志开销。

### 头部触摸 GPIO8

- 构造函数实际调用 `InitializeHeadTouchGpio()`，没有调用 `InitializeTouchSensor()`。`touch_sensor.cc` 中的电容阈值/长按参数不是当前活动链路，调这些参数不会修复现版本摸头行为。
- GPIO8 高电平有效，20ms 轮询、连续 3 次稳定后确认、800ms 触发冷却；`features/head_touch` 默认 false。可通过现有 MCP `self.touch.set_touch` 设置 `{"touch":true}`，它与屏幕触摸开关无关。
- 当前仅主页且不处于手势抑制期时触发；菜单/计时页摸头无响应是现有条件限制。开机即处于高电平时，需释放并再次触摸才产生上升沿事件。
- 开关是跨任务访问的普通 bool，主页/抑制状态也跨线程读取；建议用原子开关并将最终页面、应用状态判断与反馈调度到应用线程。
- 上拉和下拉均关闭。应先确认实际模块是主动数字输出还是裸电极、空闲电平和极性，再决定偏置；不能直接假设 GPIO 数字读取适用于任何电容电极。

**实机验收步骤（尚未执行）：**

1. 确认串口与当前固件，记录冷启动到三个输入设备初始化完成的日志，优先排除 R01。
2. 屏幕分别测试中心和四方向坐标、连续按住/松开、六个菜单项单击/长按、顶部下拉与底部上滑各 20 次；每个动作只允许一个业务结果。
3. 打开车载并重复屏幕动作，检查 QMI 50 Hz 采样、触摸、音频和电量共享总线时是否有读错/卡顿。
4. 通过 MCP 明确开启头部触摸，在主页触摸/松开 20 次，验证一次动作只唤醒一次；关闭开关后再测。记录 `Head touch GPIO8 active` 与 ignored 原因。
5. 覆盖长按不松、启动时按住、刚滑动后摸头、菜单页摸头、听说状态和车载状态；与实际产品约定比较，不把受抑制行为记成硬件故障。
6. 异常测试应在台架准备好后进行，检查传感器失联、恢复、日志和 UI 状态，不在本轮自动执行物理断接或刷写。

## 三、后续优化顺序

1. **传感器数据基础：** 先统一字节序、回读配置、核实安装轴，增加样本时间/序号、实际 Hz、I2C 错误数、最近成功读取时间和标定状态。现在只以 I2C 成功当作新样本，没有 DRDY/芯片时间戳校验，无法识别“总线正常但数据冻结”。
2. **采样与滤波：** 当前寄存器 ODR 不是 50 Hz，50 Hz 是主机轮询率。需将实际 ODR、滤波带宽和读取/下采样方案共同验证，减少混叠和共享总线开销；不要只缩短 FreeRTOS delay。
3. **冲击检测：** 当前 Bump 的 20ms 确认需要至少两个相邻超阈样本。一个 50 Hz 样本宽度的 0.6g 垂向冲击未输出 Bump。考虑峰值锁存/短窗口能量、最短显示时长和冷却，分别用单次冲击及持续振动回放验收。
4. **参数与安装：** Detector 支持 axis/sign 参数，但服务的 Reset 全部使用默认 X/+，UI/MCP/NVS 没有轴向配置。X 接近竖直时投影模小于 0.5，将无法完成校准。增加轴向设置和具体错误提示，左右方向需重新实测。
5. **输出与并发：** 车载每秒会再次调用相同 SetEmotion，当前 SetEyes 会重新设置资源并启动动画。改为事件变化/显示恢复时刷新，避免循环被重启。串行化 enable/reset/render 状态，保护 `last_car_render_request_ms`，避免多任务竞态。
6. **底座与抢占：** 原 shake 已在车载开启时抑制，但 DOA 路径仍可发送底座角度，头部触摸也仍可唤醒并切表情。明确车载时哪些动作允许，恢复时使用用户当前设置；不能把“车载渲染函数不发电机命令”等同于整个模式不会发生底座动作。
7. **职责拆分：** 当前 feature_ui.cc 同时承担算法服务、NVS、计时和 UI；菜单仍是固定标签数组加 switch，尚未达到含状态/禁用/回调的统一注册模型。先修缺陷，再分出 CarModeService、TimerService 和菜单注册数据。
