# 09-车载模式迁移与实施方案

## 目标交互

在通用下拉圆环菜单中增加车载模式项目。菜单项显示开关状态，并可进入车载设置或状态界面，
用于查看当前表情包、校准和传感器状态。关闭车载模式后停止车载显示覆盖并恢复普通喵伴交互；
仅关闭下拉菜单不应自动关闭已经启用的车载模式。

首期表情包候选为 TITA、双眼表情包、喵表情三套。菜单只负责车载模式开关和入口，表情包选择
放在长按进入的详细设置中，具体是构建期固定还是设置页切换需在实现前确认。

首版建议默认关闭，首次进入页面由用户明确开启；固定设备并静止至少两秒完成校准。

## 推荐模块划分

```text
QMI8658 50 Hz 采样
        |
        v
car::Detector（复用旧版纯 C++ 核心）
        |
        v
CarModeService（NVS、状态槽、页面生命周期、MCP）
        |
        v Application::Schedule
通用菜单项 + CarModeView + EmoteDisplay dialog
```

建议新增：

```text
main/boards/CyberVoc-Board-V2_0/car_mode/
  car_motion.h
  car_mode_service.h
  car_mode_service.cc
  car_mode_view.h
  car_mode_view.cc
```

`CyberVoc.cc` 只保留 QMI8658 初始化和样本投递。原 `imu_event_task` 的 shake 检测应并入同一
采样循环，避免同一芯片被两个任务并发读取。

## 复用与重写矩阵

| 旧版内容 | 处理 | 原因 |
|---|---|---|
| `car_motion.h` | 直接迁移后补测试 | 无 ESP-IDF 依赖，数据单位清晰 |
| 运动回放测试 | 迁移 | 可继续验证阈值、迟滞、断流和安装轴 |
| 16 个逻辑事件与优先级 | 迁移 | 已经与表情包解耦 |
| NVS 配置字段 | 迁移并调整命名空间 | enabled/pack/axis/sign 仍适用 |
| MCP 配置、校准、事件、状态 | 迁移到 `CyberVocTools` 或服务自身 | CyberKit MCP 框架兼容，但初始化位置不同 |
| 旧 `car_mode.cc` | 重写适配层 | 绑定旧板型、BMI270 和旧 Emote 内部布局 |
| BMI270 采样代码 | 不迁移 | V2.0 使用 QMI8658A |
| 32 个 EAF | 暂不全量迁移 | 5.5 MB assets 分区放不下当前资源加旧资源 |
| EAF 生成器 | 迁移/改参数 | 可用于生成更小的 V2.0 专用资源 |
| 构建脚本 | 不直接迁移 | 2.0 使用 `release.py`，不是旧版 `build.py` |

## 分阶段实施

### 阶段 0：建立可验证基线

- 原版执行 `python scripts/release.py CyberVoc-Board-V2_0`。
- 保存 app、assets、分区表尺寸和构建日志。
- 实机确认主页、番茄钟、睡眠页、语音、触摸、底座和电量功能。

### 阶段 1：IMU 采样与日志

- QMI8658 改为稳定 50 Hz，使用 `vTaskDelayUntil()`。
- 将 raw 转为 g 和 °/s；串口输出时间戳、六轴、校准状态和检测结果。
- 保留旧 shake 语义，但只产生事件，不从采样任务直接唤醒或改 UI。
- 台架验证静止时加速度模约 1g、角速度接近 0，再进行实车数据采集。

### 阶段 2：通用菜单接入与状态服务

- 将车载模式注册为通用下拉圆环菜单项，不再增加旧式循环页面。
- 状态界面显示关闭、校准中、工作中、传感器异常四种状态。
- 用有界“最新状态槽”连接采样与渲染，100 ms 左右刷新一次即可。
- 语音 Listening/Speaking、系统提示和电量告警高于普通车载动画；急刹/碰撞表情只做短暂覆盖。

### 阶段 3：最小资源集

先做一个表情包和 6 个必要资源：`cruise`、`accelerate`、`decelerate`、`turn_left`、
`turn_right`、`bump/hard_brake`。优先降低帧数、帧率或时长，并实际生成 assets.bin 测量。

资源策略按优先级选择：

1. 复用现有 `neutral/look_left/look_right/shocked/confused`，零新增或极少新增资源；
2. 加入单套精简车载 EAF；
3. 确认空间后再加入第二套表情包；
4. 不在首版擅自改变 16 MB 分区布局，除非已确认 OTA 和恢复策略。

### 阶段 4：实车标定与完整表情包

- 采集静止、起步、加速、动能回收、制动、左右转、减速带和烂路日志。
- 用回放测试调整阈值，不在实车循环中盲调。
- 验证设备安装轴和左右方向；验证坡道、手持和松动情况下的误报。
- 资源与算法稳定后再扩展 16 状态和双包切换。

## 推荐的首版状态映射

| 检测状态 | 首版显示 | 备注 |
|---|---|---|
| 未校准 | wait/文字状态 | 固定静止两秒 |
| 无明显运动 | neutral/cruise | 不宣称已知绝对车速 |
| 加速 | accelerate | 纵向正加速度 |
| 减速 | decelerate | 包含动能回收和制动，无法区分踏板 |
| 急减速 | hard_brake/shocked | 短时高优先级 |
| 左/右转 | look_left/look_right | 由重力轴角速度主判 |
| 垂向冲击 | bump/confused | 需冷却避免连续刷屏 |
| 传感器断流 | signal_lost/页面提示 | 不持续抢占系统告警 |

## 验收清单

- 下拉菜单开关和状态界面行为正确，打开/关闭菜单不会误触发语音或改变车载启用状态。
- 关闭车载模式时行为与原固件一致。
- 50 Hz 采样不阻塞共享 I2C，不影响 BQ27220、音频和触摸。
- 车载模式不驱动底座；DOA/晃动等冲突功能能在退出后恢复。
- 语音交互、电量提示和底座临时动画不会被车载刷新立即覆盖。
- 传感器断流和异常值不会导致崩溃或永久卡在某个表情。
- app 同时满足 ota_0/ota_1 升级约束；assets.bin 未超过 5500K。
- 主机回放测试、正式板级构建、烧录测试和实车测试均有记录。
