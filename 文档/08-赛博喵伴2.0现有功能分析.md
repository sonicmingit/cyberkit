# 08-赛博喵伴 2.0 现有功能分析

分析对象：`2.0/cyberkit/main/boards/CyberVoc-Board-V2_0`。

## 当前“原型菜单”的真实结构

固件没有一个带图标列表的菜单。`ui_bridge` 维护页面链表，边缘滑动时只在
`in_cycle=true` 的页面间循环：

```text
DUMMY（主页表情）
  -> POMODORO（番茄钟）
  -> SLEEP（睡眠闹钟）
  -> 回到 DUMMY
```

`PAGE_TIME_UP` 也已注册，但 `in_cycle=false`，只在闹钟结束时进入。滑动切页会先通过
`Application::Schedule()` 切到 Idle，再调用页面回调或默认切页，因此新增车载页面可以
沿用同一线程模型。

以上是分析时的现有实现，不再把下面的旧建议作为目标结构：

```text
DUMMY -> POMODORO -> SLEEP -> CAR_MODE -> DUMMY（已废弃方案）
```

根据当前项目需求，番茄钟和睡眠闹钟将移除，功能入口统一迁移到下拉圆环菜单。车载模式应作为
通用菜单中的开关或设置项接入，是否启用不能再与某个循环页面是否可见简单绑定。车载状态显示、
菜单开关和普通主页之间需要独立生命周期。

## 当前 IMU 实现

V2.0 在 I2C 地址 `0x6A/0x6B` 探测 QMI8658A，检查 WHO_AM_I `0x05`，随后启用加速度计
和陀螺仪。任务每 80 ms 读取一次 12 字节原始数据（约 12.5 Hz），比较相邻帧六轴 raw
差值；连续超过阈值 4 次且超过 10 秒冷却后触发剧烈晃动。

触发条件还受两个约束：必须位于主页，并且 NVS 中 `features/shake_enabled` 已开启。触发后
可能停止音乐、唤醒语音并设置 `confused` 表情。它适合“被人晃动”交互，不足以区分加速、
减速、转弯和路面冲击。

迁移前必须用静态放置日志确认 QMI8658A 的量程、字节序和轴方向。当前配置写入
`CTRL1=0x60`，读取端按小端合成数据；在没有实测数据前不能把这一组合视为已验证。

## 显示与抢占关系

当前至少有以下模块会改变表情或临时动画：

- 应用状态和服务端 LLM emotion：`SetEmotion()`；
- 晃动、头部触摸：`SetEmotion()`；
- 底座插入/喂食：`InsertAnimDialog()`；
- 音频分析在特定状态下会 `StopAnimDialog()`；
- 页面切换会隐藏/恢复主页 Emote 容器。

`EmoteDisplay::InsertAnimDialog()` 已提供临时动画和超时恢复机制，但同一时刻只有一个
dialog 槽。车载模式若持续刷新该槽，会与电量、底座、音频等功能竞争，因此需要一个明确
的页面生命周期和优先级适配器，不能在 IMU 任务中直接调用 UI。

## 构建与资源现状

- V2.0 使用 `scripts/release.py CyberVoc-Board-V2_0` 构建。
- `main/CMakeLists.txt` 会递归编译板级目录中的 `.c/.cc`，新增车载子目录可自动纳入。
- 配置启用 `CONFIG_FLASH_EXPRESSION_ASSETS`，板级外部 assets 路径会进入表情资源包。
- 当前 `partitions/v2/16m.csv`：`ota_0=6000K`、`ota_1=3000K`、`assets=5500K`、
  `model=300K`。OTA 槽大小不对称，后续任何应用体积增长都必须同时核对升级路径。
- 板级 assets 文件当前合计约 5.32 MB（这是源文件粗略合计，不等于最终 assets.bin 的
  精确体积）。旧版两套车载 EAF 不能在未测量最终镜像前直接加入。

## 对首版开发的约束

1. 仅在 `CyberVoc-Board-V2_0` 生效，不影响 V1.2。
2. 车载模式只改变屏幕，不自动驱动底座电机。
3. IMU 任务只采样和产生最新状态，UI 更新统一调度到应用/LVGL 安全上下文。
4. 离开 `CAR_MODE` 页面、进入语音交互、显示高优先级系统提示时必须可恢复。
5. 不把 IMU 推断描述成点火、挡位、踏板或绝对车速。
