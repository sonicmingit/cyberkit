# 10-旧版车载模式复用基线

来源：`xiaozhi-esp32-official-v2.4.2`，版本 `2.4.2-car.1`。

## 已经完成并可作为证据的工作

- BMI270 以约 50 Hz 向纯 C++ 检测器输入 g 和 °/s。
- 静止两秒估计重力方向与陀螺零偏，支持 X/Y/Z 前向轴和正负方向。
- 检测加速、减速、急减速、左右转、颠簸、断流；有低通、持续时间、迟滞和优先级。
- 配置、重新校准、事件注入和状态查询四个 MCP 工具。
- 两套表情包共 32 个 EAF；逻辑事件与资源名称解耦。
- 使用最新状态槽和最多一个待调度 UI 任务，不积压传感器事件。
- 主机测试 62/62、运动回放、EAF 解码、资源嵌入和正式构建均通过。

## 不能沿用的旧结论

- 旧版传感器是 BMI270；QMI8658A 的寄存器、量程比例和轴方向必须重新验证。
- 旧版 assets 分区为 8 MB 且有约 1.57 MB 余量；2.0 当前是 5.5 MB，空间模型不同。
- 旧版通过“应用 Idle 时显示”控制抢占；2.0 还要以 `CAR_MODE` 页面是否激活为条件。
- 旧版全脸资源需要修改 `emerg_dlg` 自动镜像和对齐；2.0 Emote 实现及 layout 必须重新
  核对，不能复制内部对象操作后假设有效。
- 旧版构建环境为 ESP-IDF 6.0.2；2.0 README 要求 >=5.4、现有记录建议 5.5.2，必须先以
  2.0 项目自己的锁定依赖完成原版构建。

## 源码迁移顺序

1. 迁移 `car_motion.h` 和对应回放测试，不接硬件。
2. 写 QMI8658 物理单位适配器，用台架数据验证。
3. 写 `CarModeService`，接 NVS/MCP，但先只输出串口状态。
4. 新增 `CAR_MODE` 页面和生命周期。
5. 先复用现有表情完成端到端验证。
6. 资源预算通过后，再迁移/重新生成专用 EAF。
