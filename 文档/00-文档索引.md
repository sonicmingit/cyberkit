# 00-喵伴 2.0 文档索引

本目录统一维护整个喵伴 2.0 固件的需求、计划、迭代和开发日志。以后新增的项目文档必须放在 `文档/` 内，不再向官方原有的 `docs/` 添加本项目记录。

## 文件结构

- `01-项目需求记录.md`：项目级需求基线、优先级、状态和验收标准。
- `02-开发日志.md`：按日期记录实际修改、验证、提交和遗留问题。
- `03-总体开发路线图.md`：项目阶段、目标和完成标准。
- `04-车载模式需求基线.md`：车载模式专项需求和约束。
- `05-上游同步与提交规范.md`：个人仓库与官方仓库同步方法。
- `06-车载模式开发说明.md`：车载模式专项开发入口。
- `07-迭代记录/`：每轮迭代的范围、计划、测试和完成结果。
- `08-赛博喵伴2.0现有功能分析.md`：板级硬件、现有页面、IMU、显示和资源现状。
- `09-车载模式迁移与实施方案.md`：旧版能力向 2.0 迁移的模块与阶段方案。
- `10-旧版车载模式复用基线.md`：旧版已验证能力、参数和不可直接沿用项。
- `11-车载表情资源筛选与转换记录.md`：TITA、猫眼和双眼资源的筛选与 EAF 转换结果。

## 持续更新规则

1. 开始开发前先更新需求状态，并建立对应迭代记录。
2. 需求变更保留编号和历史，不静默覆盖原有验收口径。
3. 每次实现后记录修改文件、测试方法、结果和 Git 提交。
4. 未编译的功能不能标为“已完成”；依赖硬件的功能还需标注实机验证状态。
5. 官方上游合并、冲突处理和回归结果也写入开发日志。

## 状态定义

- `待细化`：目标已提出，交互或技术口径仍需确认。
- `已计划`：范围和验收标准已确定，尚未实现。
- `开发中`：正在实现。
- `待验证`：实现完成，等待编译或实机验证。
- `已完成`：实现和规定验证均通过。
- `已阻塞`：存在明确且尚未解除的外部阻塞。
