# 15-TF 卡 MEPACK 表情包加载开发需求

需求编号：`需求-006`  
计划迭代：`迭代-007`  
优先级：P1  
状态：已计划  
目标硬件：`CyberVoc-Board-V2_0`，360×360 圆屏  
基线日期：2026-09-09

## 1. 交付目标

在不重新烧录固件和 assets 分区的前提下，让用户把统一格式的 `.mepack` 表情资源包复制到 TF 卡，通过喵伴的车载设置菜单扫描、查看、选择并使用表情包。

本需求完成后应形成以下闭环：

1. 用户从素材母版生成 `NNN-<pack_id>-vN.mepack`。
2. 用户将包复制到 TF 卡的 `/miaoban/packs/` 目录；挂载后的固件路径为 `/sdcard/miaoban/packs/`。
3. 固件只扫描包头、设备清单和状态索引，菜单仅列出结构及设备兼容性有效的包。
4. 用户选择表情包后，固件按当前逻辑状态读取单个 EAF 到 PSRAM，完成校验后无闪退地切换显示。
5. 重启后恢复已选包；包丢失、拔卡、损坏、读取失败或内存不足时安全回退到 Flash 内置表情。

“能枚举文件”不算完成；必须完成菜单选择、运行时播放、持久化、错误回退、固件构建和 V2.0 实机验证。

## 3. 已确认的固件现状

### 3.1 TF 卡

- `main/boards/CyberVoc-Board-V2_0/CyberVoc.cc` 的 `InitializeTFCard()` 已使用 `esp_vfs_fat_sdmmc_mount()` 挂载 TF 卡。
- 挂载点由 `main/boards/CyberVoc-Board-V2_0/config.h` 定义为 `/sdcard`。
- 当前使用 SDMMC 1-bit：CLK GPIO48、CMD GPIO45、D0 GPIO47；`max_files=5`，挂载失败不会格式化卡。
- 当前挂载结果和 `sdmmc_card_t*` 只停留在初始化函数内，没有提供给表情包模块的稳定状态接口，也没有现成的插拔事件管理。
- 设备未确认存在独立卡检测引脚，因此首版不能依赖硬件热插拔中断。启动扫描加菜单“重新扫描”是最低可用策略；运行中拔卡必须通过 I/O 错误安全处理。

### 3.2 车载表情选择

- `main/boards/CyberVoc-Board-V2_0/car_mode/car_mode_service.cc` 目前只有 `int pack`，值域被限制为 0/1。
- 现有 NVS 命名空间为 `car_mode`，旧键为 `pack`；0 对应内置 TITA，1 对应内置默认表情。
- 运行时通过 `car_<tita|default>_<state>` 拼接资源名，再调用 `EmoteDisplay::ShowCarEmotion()`。
- `main/boards/CyberVoc-Board-V2_0/customer_ui/feature_ui.cc` 的“切换表情”目前直接执行 `1 - pack`，界面也只显示“TITA”或“默认”。

### 3.3 显示数据生命周期

- `main/assets.cc` 将整个 Flash assets 分区内存映射后，把映射区内的裸指针交给显示层。
- `main/display/emote_display.cc` 的 `AddEmojiData()` 当前只保存 `const void* + size`；`gfx_anim_set_src()` 在动画播放期间仍会读取该内存。
- 因此不能把临时读文件缓冲区传给现有接口后立刻释放。TF 表情需要一个明确的所有权模型，确保旧动画已经在 LVGL/显示线程停止或替换后，旧 PSRAM 缓冲区才被释放。

## 4. 范围

本需求包括：

- 在 V2.0 板级代码中暴露只读的 TF 挂载可用状态，不重复挂载、不自动格式化。
- 扫描 `/sdcard/miaoban/packs/` 下扩展名为 `.mepack` 的普通文件。
- 按 MEPACK v1 解析包头、JSON 清单和固定状态索引，执行有界、溢出安全的结构及兼容性检查。
- 建立内置包与 TF 包统一的运行时身份模型，至少包含 `source`、`pack_id`、`version`、`display_name`。
- 车载设置页从二选一切换改为表情包列表，支持刷新、选择、当前包标记和错误提示。
- 后台按状态读取一个 EAF 到 PSRAM，校验后切换显示；不得在 IMU、100 ms 车载轮询或 LVGL 高频回调内做文件 I/O 或 SHA-256。
- 持久化选择并兼容迁移旧 `car_mode/pack` 整数键。
- 处理无卡、空目录、非法包、版本不兼容、状态缺失、拔卡、短读、校验失败、PSRAM 不足和快速连续切换。
- 保留至少一个 Flash 内置包作为最终回退，不因启用 TF 功能而移除恢复路径。
- 增加可复现的解析器测试、回归测试、完整固件构建和实机验证记录。

## 5. 明确不在本需求内

- 不实现从网络、OTA 服务或应用商店下载表情包。
- 不实现第三方包市场、付费、账户同步或云端包管理。
- 不修改 MEPACK v1 二进制格式，也不新增 ZIP 解压路径。
- 不把 `.mepack` 当成可执行插件；包内只能包含清单、索引和 EAF 数据。
- 不在本轮实现正式发布签名体系。v1 本地 TF 包允许 `unsigned`，但 UI/日志不得将 SHA-256 描述为来源认证。
- 不改变 QMI8658 事件识别阈值、车载状态机含义、基础语音抢占逻辑或底座控制逻辑。
- 不要求通过 TF 热插拔中断自动刷新；没有可靠检测引脚时使用显式重新扫描。
- 不顺带重构无关板型。非 `CyberVoc-Board-V2_0` 的行为必须保持不变。
- 不把构建期表情选择器作为本需求完成条件；它继续属于 `需求-005`。

## 6. 运行时数据模型

建议定义稳定结构，名称可按项目风格调整，但职责不可混合：

```text
ExpressionPackId
├── source        builtin | tf
├── pack_id       稳定小写 ASCII 标识
└── version       内容版本

ExpressionPackDescriptor
├── id
├── display_name
├── file_path     仅 TF 包具有
├── fallback_state
├── states[]      状态 ID、offset、size、sha256、fps、loop、width、height、frames
└── validation    可用状态及错误原因

OwnedEafBuffer
├── PSRAM 地址
├── 有效字节数
├── 状态元数据
└── 明确释放者/引用计数
```

持久化选择使用三个字段，不再用整数表达任意扩展包：

```text
NVS namespace: car_mode
pack_source:    "builtin" | "tf"
pack_id:        例如 "tita"、"default"
pack_version:   整数内容版本
```

迁移规则：

1. 新字段完整存在时使用新字段。
2. 新字段不存在时读取旧 `car_mode/pack`：0 迁移为 `builtin/tita`，1 迁移为 `builtin/default`。
3. 成功保存新字段后可以保留旧键用于降级兼容，但新逻辑不得继续以旧键作为真实来源。
4. TF 包当前不可用时，不覆盖用户保存的目标身份；本次启动临时使用内置回退。重新扫描发现原包后允许恢复，避免一次拔卡永久丢失选择。

## 7. 模块与接口方案

### 7.1 TF 存储状态

在 V2.0 板级实现中增加小型只读状态接口，例如 `IsTfCardMounted()`；不要让表情模块再次调用挂载函数。挂载成功后保存状态，挂载失败记录明确错误。

如果实现重新挂载：

- 必须串行化 mount/unmount/scan/read；
- 不能在仍有打开文件或正在读动画时卸载；
- 不得设置 `format_if_mount_failed=true`；
- 没有硬件确认前，不以轮询 GPIO 电平判断卡是否存在。

### 7.2 MEPACK 只读解析器

建议新增独立于 UI 和车载状态机的只读解析模块，例如：

```text
main/boards/CyberVoc-Board-V2_0/car_mode/mepack_reader.h
main/boards/CyberVoc-Board-V2_0/car_mode/mepack_reader.cc
```

解析器负责：

- 读取并验证 128 字节固定包头；
- 验证魔数、schema、固定长度、保留区、总长与实际 `stat` 文件大小；
- 使用 64 位中间值检查所有加法、乘法、offset/size，拒绝整数溢出和越界；
- 对 manifest 长度、状态数量和单状态大小设置编译期上限；
- 校验 manifest SHA-256，解析有界 JSON；
- 比对 manifest 和 96 字节固定索引中的状态集合及全部关键元数据；
- 校验 board、360×360、loader schema、EAF encoding 和 `min_firmware`；
- 加载状态时定位 payload，执行完整读取、状态 SHA-256 和 EAF 基本结构校验。

建议首版安全上限：最多登记 32 个 TF 包、每包最多 64 个状态、manifest 不超过 64 KiB。单状态最大字节数不要凭经验写死，应根据 V2.0 实测可用 PSRAM和现有合法包最大状态确定，并在编译期配置；超过上限必须拒绝，不能尝试分配。

扫描阶段只需验证元数据区。整包 payload SHA-256 可以作为后台诊断，但不能阻塞菜单；实际播放前必须校验目标状态在索引中记录的 SHA-256。这样满足随机读取，也能在真正使用损坏状态前阻止显示。

### 7.3 包注册表和选择管理器

建议增加 `ExpressionPackManager` 或同等模块，集中负责：

- 注册 Flash 内置包；
- 后台扫描 TF 目录并生成不可变描述符快照；
- 向 UI 返回快照，不让 UI 直接持有文件句柄；
- 接收“选择包”和“请求状态”命令；
- 合并短时间内重复或过期的状态请求；
- 维护当前选择、实际使用来源、上一次错误和缓存；
- 在校验及显示提交成功后才保存新选择；
- 失败时保留当前有效动画，随后按回退矩阵处理。

表情状态请求应继续使用 `cruise`、`wait`、`accelerate` 等逻辑状态 ID。`car_mode_service.cc` 不应再拼接 TF 资源名或直接打开文件，只向管理器请求逻辑状态。

### 7.4 后台读取和请求去重

所有 TF I/O、JSON 解析、SHA-256 和 PSRAM 分配在专用 worker task 中进行。推荐流程：

```text
车载状态变化
  → 提交 {generation, pack identity, logical state}
  → worker 丢弃已过期请求
  → 查状态；缺失则改请求同包 cruise
  → 打开包、seek、分配 PSRAM、完整读取
  → 校验状态 SHA-256 和 EAF 结构
  → 在 Application/LVGL 安全上下文提交显示
  → 显示接管新缓冲区所有权
  → 确认成功后释放旧缓冲区
```

必须为请求携带递增 generation/token。用户换包或车辆状态快速变化后，较早读取即使成功也不能覆盖较新的选择。队列不得无限增长；保留最新目标即可。

### 7.5 PSRAM 缓存和所有权

- 使用 `heap_caps_malloc(size, MALLOC_CAP_SPIRAM | MALLOC_CAP_8BIT)` 或等价 RAII 包装分配动画数据。
- 最低要求缓存当前动画；可额外缓存所选包的 `cruise`，但总缓存必须有明确预算和回收策略。
- 不允许把栈内存、临时 `std::vector` 数据或读文件缓冲区裸指针交给动画后立即释放。
- 显示层需新增“带所有权的数据源”接口，或提供等价的完成/替换回调。仅延长 manager 对裸指针的猜测性持有不算可靠实现。
- 新动画读取、校验或显示提交失败时，不先释放旧动画。
- 停止车载模式、语音页面抢占、切回内置包以及析构时都必须在正确线程释放动态数据。
- 记录每次分配前后的可用 PSRAM、最大连续块、动画字节数和失败原因，便于实机定位碎片问题。

### 7.6 菜单交互

把车载设置中的“切换表情”从二进制切换改为进入列表页。列表至少显示：

- 当前选中标记；
- 来源：“内置”或“TF 卡”；
- `display_name`；
- 内容版本，例如 `v1`；
- 不可用包的简短原因，或在页面底部汇总“已忽略 N 个无效包”。

必须提供“重新扫描 TF 卡”。扫描期间显示忙碌状态但不阻塞触摸、LVGL 或当前动画。无 TF 卡或无有效包时，内置 TITA 和默认表情仍可选择。

选择流程：

1. 用户点击候选包。
2. 后台加载候选包的当前逻辑状态；缺失时尝试候选包 `cruise`。
3. 读取、校验和显示提交全部成功后，才更新当前标记及 NVS。
4. 失败时仍显示旧包，界面提示可理解的失败原因。

不要在 UI 中展示绝对路径、哈希全文或解析器内部错误码；完整信息写日志。

## 8. 文件发现与安全规则

- 只扫描固定目录 `/sdcard/miaoban/packs/` 的直接子文件，不递归。
- 仅接受规范文件名 `NNN-<pack_id>-vN.mepack`；拒绝隐藏文件、临时文件、目录、符号链接和包含路径分隔符的名称。
- 规范文件名中的编号、`pack_id`、版本必须与包清单一致。
- 不根据 JSON 提供的路径访问其他文件；payload 只能从当前已打开 `.mepack` 的有界 offset 读取。
- 同一个 `source + pack_id + version` 出现多个文件时全部标记冲突，不以目录枚举顺序随机选择。
- 同一个 `pack_id` 的多个版本可以并存；恢复持久化选择时匹配精确版本，不静默升级。菜单可按名称、版本降序做确定性排序。
- 任何用户可控字符串复制到固定缓冲区时必须保证长度和终止符；日志不得用其作为格式字符串。
- 单个坏包不得中止整目录扫描，错误需带文件名和原因记录。

## 9. 回退矩阵

| 场景 | 必须行为 |
|---|---|
| 启动时无 TF 卡 | 使用保存的内置包；若保存的是 TF 包则临时回退内置默认包并保留目标身份 |
| 目录不存在或为空 | 菜单仍显示内置包，并允许重新扫描 |
| 包头/清单/索引非法 | 忽略该包，继续扫描其他包 |
| 目标状态缺失 | 尝试同一包 `cruise` |
| 同包 `cruise` 也不可用 | 使用 Flash 内置中性/巡航表情 |
| 状态读取、短读或 SHA-256 失败 | 不替换当前有效动画；记录错误并回退 |
| PSRAM 分配失败 | 不破坏当前动画；回退内置包并记录内存数据 |
| 播放中拔卡 | 已完整缓存的当前动画可继续；下一次未缓存状态读取失败后回退 |
| 读取期间用户再次换包/换状态 | 旧 generation 的结果丢弃，不能覆盖最新请求 |
| 语音或更高优先级页面抢占 | 沿用现有 `StopCarEmotion()` 行为，释放动态资源不得造成悬挂指针 |

最终 Flash 回退包必须完全不依赖 TF 卡和 PSRAM 中的 MEPACK 缓存。

## 11. 测试要求

### 11.1 主机/组件测试

解析器至少覆盖：

- 合法 `004-default-v1.mepack` 的 19 个状态和元数据；
- 错误魔数、schema、包头长度、保留区、总长度；
- manifest 哈希错误、非法 JSON、字段缺失、过长字符串；
- 索引数量/长度不一致、重复状态、非法状态名；
- offset 加法溢出、payload 前后越界、重叠区间、未对齐；
- board、分辨率、encoding、loader schema、最低固件不兼容；
- 截断文件、短读、状态 SHA-256 错误、EAF 头或内部长度错误；
- 包数量、状态数量、manifest 和状态大小超过上限；
- 重复包身份及确定性排序；
- 新旧 NVS 选择迁移和 TF 暂时不可用时不覆盖目标身份。

禁止为了测试重新实现一套与设备解析器无关的 Python 逻辑后只测 Python；核心边界检查应直接覆盖将进入固件的 C/C++ 解析代码。

### 11.2 固件回归

- `CyberVoc-Board-V2_0` 全量构建通过，分区不溢出。
- 现有车载模式、TITA/默认内置包、菜单、计时器、语音抢占、IMU 和触摸测试不回退。
- 未插 TF 卡时启动日志清楚但不过度刷屏，不重启、不阻塞进入主页。
- 扫描及动画读取期间，车载 100 ms 心跳和 UI 不进行同步文件操作。
- 快速连续切换状态和包时最终画面与最后请求一致，没有旧结果反向覆盖。

### 11.3 V2.0 实机验收

使用 FAT32 TF 卡建立 `/miaoban/packs/` 并放入 `004-default-v1.mepack`，记录卡容量、品牌/速度等级和固件版本。至少验证：

1. 无卡开机、带卡开机、空目录、重新扫描。
2. 菜单正确显示“默认表情 v1 / TF 卡”，选择后可播放。
3. 通过调试状态或测试入口逐一请求包内 19 个状态，确认方向、尺寸、帧率、循环和结束行为。
4. 播放巡航时触发加速、减速、急刹、颠簸、左右转、信号丢失，事件恢复正确。
5. 动画播放中拔卡，当前缓存不中断；下一状态安全回退且设备不重启。
6. 使用损坏包、截断包和不兼容清单，坏包被拒绝但内置包仍可用。
7. 连续切换包和状态至少 200 次，记录启动/结束的 internal heap、PSRAM free、largest block 和最低余量；无持续下降趋势或悬挂访问。
8. 在播放、菜单扫描和状态切换期间触发语音交互，显示层正常让位并能恢复。
9. 重启后恢复 TF 选择；随后无卡重启可回退，重新插卡并扫描后可恢复原选择。

性能验收以“不阻塞实时路径”为硬条件：LVGL/车载轮询中单次同步工作不得包含文件读取或全包哈希。首次状态切换耗时、扫描耗时和 PSRAM 峰值必须实测记录；如需制定毫秒阈值，应以目标 TF 卡实测基线写入迭代记录，不能伪造结果。

## 12. 完成标准

只有同时满足以下条件才能把 `需求-006` 标为已完成：

- MEPACK v1 解析及按状态读取已进入 V2.0 固件，且没有整包载入内存。
- 车载设置可以列出、重新扫描和选择 TF 表情包；内置包始终可用。
- 动态 EAF 的 PSRAM 所有权和显示释放时机有明确代码实现与测试证据。
- 旧 `car_mode/pack` 配置完成兼容迁移，新选择可跨重启恢复。
- 所有表内失败场景均有安全回退，不发生重启、死锁、悬挂指针或无限日志。
- 主机/组件测试通过，V2.0 ESP-IDF 全量构建通过。
- 使用 `004-default-v1.mepack` 完成上述真实 TF 卡实机验收并记录固件、包哈希、内存和结果。
- 文档索引、需求记录、开发日志和迭代记录同步更新。
