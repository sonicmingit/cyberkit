# 车载表情包命名规则

版本：v1.3。新表情包、同包升级、内部状态文件和 MEPACK 设备包均遵守本规则。

## 1. 表情包目录名

格式：`NNN-表情包名称-v版本号`

- `NNN`：三位十进制开发序号，从 `001` 递增。序号在表情包首次建立时分配，此后永久保留且不回收。
- `表情包名称`：简短、稳定、可辨认的中文展示名；允许保留必要的品牌英文，不使用空格、斜杠或“最终版”等状态词。
- `v版本号`：小写 `v` 加正整数，从 `v1` 开始。禁止省略版本、使用 `v01`，或用日期替代版本。

示例：

- 同一薄荷猫咪升级：`002-薄荷猫咪-v1` → `002-薄荷猫咪-v2`。
- 新建另一种视觉角色：分配 `004-新名称-v1`，不能复用 `001`～`003`。
- 只有素材修复、补帧、调色、状态增补或编码变化时递增版本；预览图按同一批 GIF 重新生成，不单独改变包版本。

现有编号登记：

| 编号 | 固定名称 | 稳定 `pack_id` | 当前版本 |
|---:|---|---|---:|
| 001 | TITA大眼仔 | `tita` | v1 |
| 002 | 薄荷猫咪 | `cat` | v1 |
| 003 | 暖白双眼 | `soft_eyes` | v2 |
| 004 | 默认表情 | `default` | v1 |

`004` 已分配给默认表情；后续全新表情包使用下一个未占用编号。同一编号不得同时对应两个名称或两个 `pack_id`；旧版本保留时，不覆盖其文件。

`003-暖白双眼-v1/` 是规则生效前的历史版本，当前候选升级版为 `003-暖白双眼-v2/`。

## 2. 单个状态素材名

GIF 与 EAF 统一使用：`car_<state>.gif`、`car_<state>.eaf`。

- `<state>` 只使用小写 ASCII `snake_case`，不在文件名中重复包名或版本号。
- 同一状态的 GIF/EAF 主文件名必须完全相同。
- 视觉包由上级目录和 `pack_id` 区分；固件打包后可以登记为 `car_<pack_id>_<state>`。

固定状态与预览中文名：

| `<state>` | 中文标签 | `<state>` | 中文标签 |
|---|---|---|---|
| `wake` | 唤醒 | `move_off` | 起步 |
| `accelerate` | 加速 | `cruise` | 巡航 |
| `turn_left` | 左转 | `turn_right` | 右转 |
| `turn_end` | 回正 | `reverse` | 倒车 |
| `decelerate` | 减速 | `hard_brake` | 急刹 |
| `bump` | 颠簸 | `wait` | 等候/校准 |
| `arrive` | 停车 | `sleep` | 休眠 |
| `night` | 夜间 | `signal_lost` | 信号中断 |

新增状态前先确认输入来源、生命周期和回退，再在本表、预览生成工具及固件状态映射中同时登记。不要私自用近义词新建重复 ID，例如同时出现 `brake_hard` 与 `hard_brake`。

### 待机变体命名

- 待机动画统一使用 `car_idle_NN.gif` 和 `car_idle_NN.eaf`，其中 `NN` 是从 `01` 开始的两位十进制序号。
- 新建或升级包至少包含 `car_idle_01`、`car_idle_02`、`car_idle_03`；增加变体时连续使用 `04`、`05`，不得跳号、使用 `00` 或改成 `idle_a`。
- 同一家族后续版本保留已有待机编号所代表的设计方向；替换内容或新增变体时递增表情包版本，不给文件名单独附加 `v2`、`final` 等后缀。
- 中文总览依次显示“待机 1”“待机 2”“待机 3”。`cruise`、`wait`、`sleep` 不得重命名为待机变体，也不计入最低三种。
- 001～003 的 v1 包是规则生效前的历史版本，可原样保留；从其 v2 起必须补齐待机动画组。新编号包从 v1 起即执行本规则。

## 3. 固定文件名

### 3.1 预览审批阶段

静态设计稿转动态表情时，第一阶段仅输出以下两个固定名称的审阅文件：

- `全部表情预览.gif`：展示全部状态的动态方案，画面标签使用中文。
- `全部静态表情预览.png`：展示同一批动态方案的代表帧，状态顺序和中文标签与动态总览一致。

预览文件名不附加“最终版”“满意版”“final”等状态词。评审中的修改直接更新本轮两份预览；用户明确确认前，不创建正式 `gif/car_<state>.gif`、`eaf/car_<state>.eaf` 或 `eaf/manifest.json`。

### 3.2 正式交付阶段

每个编号包根目录固定使用：

- `README.md`
- `全部表情预览.gif`
- `全部静态表情预览.png`
- `gif/`
- `eaf/`
- `eaf/manifest.json`

用户确认预览后，再按上述正式目录生成逐状态资源。总览画面内只显示上表及待机变体规则定义的中文标签；不要把 `WAKE`、`TURN_LEFT` 等英文状态直接画进总览。实际 360×360 动画帧不含这些标签。

## 4. README 与清单版本

- 单包 README 标题写明编号、名称和版本，并记录 `pack_id`、画布、状态数量、待机动画组、随机权重/播放单元、来源、缺失项、回退和验证状态。
- `manifest.json` 中 `source` 指向同包 `gif/` 的同名文件，`output` 指向 EAF 文件名；涉及 EAF 内容变化时重新计算帧数、大小和 SHA-256。
- 只移动目录或将 `tita_<state>` 规范化为 `car_<state>`、且文件内容未变化时，SHA-256 保持不变，但清单中的路径/文件名必须同步更新。

## 5. MEPACK 设备包命名

固定格式为 `NNN-<pack_id>-vN.mepack`：

- `NNN` 与母版目录的三位编号一致；
- `<pack_id>` 与母版 README 中登记的稳定 ID 一致，只允许小写 ASCII `snake_case`；
- `vN` 与母版内容版本一致，不使用日期、`latest`、`final` 或构建序号代替；
- 例如 `004-默认表情-v1/` 生成 `设备资源包/004-default-v1.mepack`；
- 整包校验文件命名为同名加 `.sha256`，例如 `004-default-v1.mepack.sha256`。

设备包文件名使用 ASCII，中文展示名称保存在包内清单。`.mepack` 不放入母版目录，不改变母版的五项固定交付结构。同一母版和相同打包参数重复生成时文件名及 SHA-256 必须相同；若 EAF、FPS、循环、回退或清单运行语义改变，应递增母版内容版本后重新打包。
