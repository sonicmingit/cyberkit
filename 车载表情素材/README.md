更新日期：2026-09-08。

## 标准交付结构

以后每个表情包统一生成以下内容：

```text
NNN-表情包名称-v版本号/
├── eaf/
│   ├── car_<状态>.eaf
│   └── manifest.json
├── gif/
│   └── car_<状态>.gif
├── README.md
├── 全部表情预览.gif
└── 全部静态表情预览.png
```

- `gif/` 与 `eaf/` 的同名状态必须一一对应。
- `全部表情预览.gif` 和 `全部静态表情预览.png` 的画面标签统一使用中文；固件状态文件名继续使用稳定的 ASCII 逻辑 ID。
- `README.md` 必须记录包编号、名称、版本、`pack_id`、状态覆盖、缺失回退、来源和验证状态。
- 设计源文件不进入编号包目录，避免固件打包时误收集大文件。

## 规范入口

- [`01-基础设计规范.md`](01-基础设计规范.md)：画布、安全区、造型、颜色、动画与检查基线。
- [`02-素材使用规范.md`](02-素材使用规范.md)：固件选包、复制、映射、回退、容量和验证流程。
- [`03-命名规则.md`](03-命名规则.md)：包编号、版本、状态文件名和中文预览名称。

## 生成预览

[`工具/生成表情预览.py`](工具/生成表情预览.py) 会校验标准目录、GIF/EAF 对应关系、360×360 GIF、EAF 文件头及 manifest 的帧数、大小和 SHA-256，并重新生成两张中文总览。脚本依赖 Pillow，从仓库根目录执行：

```powershell
python 车载表情素材/工具/生成表情预览.py
```

可以只处理指定包：

```powershell
python 车载表情素材/工具/生成表情预览.py 002-薄荷猫咪-v1
```

预览生成和结构检查不等于 EAF 已通过实机播放；颜色、方向、裁切、帧率、内存和资源分区仍需按素材使用规范验证。
