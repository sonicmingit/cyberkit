# 车载表情基础设计规范

版本：v1.2。适用画布：喵伴 2.0 的 360×360 圆形屏。

本规范从现有 TITA 大眼仔、薄荷猫咪和暖白双眼三套素材提炼，作为后续表情包的最低共同基线。它约束可读性、状态语义和设备安全，不要求所有表情包采用同一种角色或颜色。

## 1. 画布与安全区

- 成品 GIF 与 EAF 固定为 360×360；坐标原点在左上，屏幕中心为 `(180, 180)`。
- 背景使用纯黑 `#000000`。最终动画不保留分镜网格、设备边框、白底或未处理的透明边缘。
- 眼睛、嘴、瞳孔等核心识别元素尽量收在以屏幕中心为圆心、半径 145 px 的核心安全区内。
- 拖尾、星芒等短时辅助效果可以进入半径 165 px 的扩展区，但不能依赖圆屏四角传达信息，也不能长期贴边闪动。
- 方向以“观看屏幕的人”为准：`turn_left` 看向画面左侧，`turn_right` 看向画面右侧。固件若做镜像，必须在接入清单中显式记录。

## 2. 角色与视觉一致性

- 每套表情包先定义中性巡航姿态，并固定眼组中心、眼距、基准尺寸和主要颜色；其他状态从该锚点变化。
- 同一状态相邻帧不得出现无意的轮廓漂移、眼距跳变、颜色抖动或背景亮度变化。
- 情绪优先通过眼形、视线、压缩、拉伸、眨眼和小幅位移表达。辅助线、星芒和点状提示只作增强，不能盖过主体。
- 实际动画画面不放文字。箭头、速度数字、警告符号等强语义元素只有在固件确实具备对应可信输入时才可使用。
- 360×360 成品中的关键细线建议不小于 3 px；缩到设备实际观看距离后仍应可辨认。

### 2.1 从静态设计稿生成动态表情

- 可以使用包含多种状态的静态表情设计图作为动态制作依据。静态图只定义角色、构图、关键姿态、颜色关系和状态语义，不直接视为可播放动画帧。
- 每个静态表情应先拆分为眼睛、瞳孔、眼睑、嘴、腮红、提示线、光效等可独立运动的视觉部件，再围绕原静态姿态补出进入、变化、情绪峰值和恢复/循环衔接；原静态姿态通常作为最有代表性的关键帧保留。
- 动作必须服务状态语义。例如转向使用视线与局部拖尾，加速使用压缩后前探，急刹使用预备、挤压和回弹，待机使用不同节奏的眨眼、视线或微表情。不能给所有状态套用同一种运动模板。
- 禁止只对整张静态图片或整个圆形图标做左右晃动、上下漂移、反复缩放、旋转、随机抖动或滤镜闪烁来冒充动态表情。颠簸等确需整体位移的状态，也必须同时包含局部形变、惯性差和恢复过程。
- 动态表情继承静态稿的背景、主色、辅色及功能色语义。新增的拖尾、光晕、粒子和过渡色应从原有颜色自然延伸，保持相同色相家族、亮度层级和使用场景；不得无依据加入抢眼新颜色，或让同一功能色在动画中改变含义。
- 静态设计图中的标题、英文状态名、网格、圆形边框和排版背景仅用于审阅，不进入 360×360 动画画面。输出前需重建黑底画布并检查圆屏裁切，而不是直接裁切后晃动原图。

## 3. 颜色、亮度与闪烁

- 每套建议使用一种主色和最多两种点缀色，保证黑底上的主体对比度；不要用大面积低对比灰表现关键状态。
- 大面积亮暗变化要平滑，禁止用高频全屏闪烁表达急刹、颠簸或故障。短促冲击优先使用形变和局部辅助线。
- 夜间优先由固件统一降低整体亮度，避免为每个状态复制一套夜间资源。`car_night` 可保留为风格示例或安静待机状态，但不能覆盖安全相关事件。
- 切换状态时保持黑色背景一致，避免先闪回默认表情或白帧。

## 4. 动画节奏

- 新制作的连续动画以 20 FPS 为设计起点，再根据 EAF 容量和设备实测调整；现有四关键姿态原型与 TITA 15 FPS 素材是已记录的例外，不据此宣称最终流畅度。
- 常驻循环状态应大部分时间稳定，眨眼或视线变化低频发生；不要把四个关键姿态等间隔高速循环。
- 加速、减速、急刹、颠簸等瞬态动画应有明确进入、峰值和恢复姿态，并由固件设置驻留上限与冷却时间。
- 左右转可以进入后保持末帧，直到可信转向状态结束；结束后根据实时状态恢复，不播放过期事件。
- 单次动画的末帧必须明确：保持、回到巡航，或由播放器选择当前状态。这个策略记录在单包 README 或清单中。

### 4.1 待机动画组

- 本规则生效后新建或升级的表情包，默认至少制作 3 个彼此独立的待机动画，依次命名为 `car_idle_01`、`car_idle_02`、`car_idle_03`；更多变体按连续编号追加。
- 三个动画必须在眨眼节奏、视线、姿态、微动作或停顿编排上具有可辨认差异，且各自能够安全完整播放。不得复制同一文件、只改文件名或只改无意义元数据来凑数量。
- 每个待机动画以“一次完整播放”为一个展示单元。随机选择由固件在单元边界执行，不在逐帧刷新中反复抽选，避免跳帧和高频切换。
- 默认等概率选择；若需要权重、循环次数或特殊时长，必须在单包 README 或资源清单中明确记录。
- `car_cruise`、`car_wait` 和 `car_sleep` 分别表示巡航中性、等候/校准和休眠，不计入 3 个待机动画的最低数量。

## 5. 状态语义边界

当前固件核心状态为：巡航、等候/校准、加速、减速、急刹、颠簸、左转、右转、信号中断。完整设计集还可以包含唤醒、起步、回正、倒车、停车、休眠和夜间。

- 不用普通 IMU 加速度宣称已识别点火、绝对车速、挡位、目的地或踏板动作。
- `car_reverse` 只有在存在可信倒车输入时使用；否则不得自动播放。
- `car_signal_lost` 表示传感器/数据不可用，不继续展示过期的转弯或制动状态。
- 素材缺少专用状态时必须声明回退，不把充电、音乐或其他无关动画改名冒充。

## 6. 交付前视觉检查

- [ ] GIF 和 EAF 均为 360×360，黑底，主体未进入危险裁切区。
- [ ] 左右方向以观看屏幕为准，并完成镜像检查。
- [ ] 中性锚点、轮廓、眼距、颜色和背景在相邻帧中稳定。
- [ ] 从静态稿生成的动画包含有语义的局部运动、形变和完整节奏，不是整图晃动、缩放或滤镜循环。
- [ ] 新增光效和过渡色由静态稿原有色彩自然延伸，功能色含义保持一致。
- [ ] 循环首尾无明显跳变；单次动画的结束策略已记录。
- [ ] 新建或升级包至少包含 3 个内容不同、可独立完整播放的待机动画，编号从 `car_idle_01` 连续递增。
- [ ] 无全屏高频闪烁、意外白帧或大面积亮度突变。
- [ ] 动态总览和静态总览包含包内全部状态，标签均为中文。
- [ ] 在 360×360 圆屏实机检查颜色、裁切、帧率和夜间亮度；未实测时明确标为“待实机验证”。
